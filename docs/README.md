**In one paragraph.** This corpus describes a system that is mostly designed and
barely built, and the documents are organised so that distinction stays visible:
`architecture/` holds the target design, `review/` holds frozen evidence about
what was true on a date, `STATUS.md` is generated and holds what is true now, and
`figures/` holds diagrams that are generated rather than drawn. If you read only
one thing, read `architecture/AETHRION_ARCHITECTURE.md`; if you want to know what
actually runs, read `STATUS.md`.

**The distinction that matters:** a *proposal* argues for something; a *decision
record* fixes it and says who decided; a *reference* describes what was decided
elsewhere. Reading a proposal as a description is the most common way to
overestimate this repository.

## 3. `review/` — frozen evidence

Everything here records what was true on a date and is **never edited to match
the present** — `DOCUMENT_STANDARD.md` §3 rule 4. Live status lives in
`STATUS.md`, which is generated.

## 3.3 `READY.md` and `EXECUTING_A_WORK_PACKAGE.md` — how V1 is actually run

`READY.md` is generated and answers one question: *what can be started today*. A
package is ready when its status is `NOT_STARTED` and every hard dependency is
`ACCEPTED` — not `TECH_COMPLETE`, because issuance is not acceptance. At t0 the
answer is one package, WP-001, and that is the plan working rather than the plan
stuck: WP-001 is what authorises the programme.

`EXECUTING_A_WORK_PACKAGE.md` is the loop around it — start, do the work, issue
evidence, mark technically complete, have someone who is not the producer accept
it. Every transition runs through `scripts/progress.py`, which refuses what the
plan forbids and cites the document that forbids it. Its §5 lists what still has
to be done by hand, because a runbook implying more automation than exists is
worse than no runbook.

## 3.4 `V2_CANDIDATES.md` — what is deliberately not V1

V1 is the sealed commissioning plan; its completion criterion is the go-live
checklist. Anything proposed after that freeze is V2, and this register is where
it waits. It sits outside the hash seal on purpose: a V2 candidate filed inside
the V1 baseline would move the finish line while appearing to be part of it.

Six entries today, five of them technical renames that were refused during the
AETHRION migration because they break import paths, a schema field or a signed
attestation. The sixth is a mirror-completeness gap.

## 3.5 `branding.md` and `assets/` — what the project is called

`branding.md` fixes one thing: the project is **AETHRION**, its descriptor is
**Agentic Intelligence Research Layer**, and `AIRL` is the abbreviation of that
descriptor rather than the product name. It also lists, by name, every place the
old acronym is deliberately kept — a metadata namespace, a schema field, two
Python packages, a systemd unit, an attestation profile — so that a future
reader can tell a retained identifier from a missed rename.

`assets/branding/` holds the logo and the rule that keeps one file canonical and
every other copy a projection of it. `assets/branding/README.md` names the three
documents the logo is allowed to appear in, and why it appears nowhere else.

## 4. `figures/` — generated diagrams

Five figures, produced by `scripts/fig_*.py`, checked for drift and for text
containment. Editing an SVG by hand is a defect. See `figures/README.md` for the
inventory, the design system and the palette.

## 5. Conventions

`DOCUMENT_STANDARD.md` defines the required structure, the controlled status
vocabulary and the honesty rules every document here follows. Three of those
rules are enforced mechanically:

```bash
python3 scripts/check_doc_consistency.py   # declared counts match the repository
python3 scripts/check_stale_claims.py      # no prose the repository has outgrown
uv run python scripts/write_status.py --check
```
